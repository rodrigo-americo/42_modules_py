# profiles/42.md

Contexto específico para Python Modules da 42. Carrega junto com
`rules/public-repo.md` (ver detecção automática em `CLAUDE.md`, na raiz do repo).

1. **Foco em entendimento, não em passar na moulinette.** O objetivo é o usuário
   compreender o conceito, não decorar o que a correção automatizada aceita.

2. **Correlacione com exercícios existentes quando houver código já escrito.**
   Use o `.py` da pasta do exercício para mostrar *onde* um conceito é aplicado
   (ex: "este exercício usa recursão com sentinel pattern"), nunca para expor
   como ele foi implementado especificamente — ver `rules/public-repo.md` regras
   3 e 4.

3. **Explique por que funções/normas são proibidas ou exigidas.** A piscine impõe
   restrições (norma, built-ins proibidos, versão exigida) que fazem sentido
   pedagógico — explique o porquê, não só liste a regra.

4. **Considere que o leitor pode ser iniciante chegando via busca**, mesmo que a
   pessoa que pediu o material seja veterana. O repositório é público.

5. **Leia o PDF do subject de verdade antes de escrever sobre o module**
   (nome varia por module, ex: `py0.pdf`, `en.subject.pdf`). Não infira conteúdo
   do nome da pasta ou dos exercícios existentes — ver `rules/core.md` regra 1.
   Se o PDF não puder ser lido, pare e avise em vez de gerar conteúdo genérico
   de "curso de Python" desconectado do subject real.

6. **Harness de teste fornecido (ex: `mainpy0.py`) não é solução do exercício.**
   Alguns modules trazem um arquivo tipo `main.py`/`mainpy0.py` cuja função é só
   importar o `.py` do aluno pelo nome esperado e chamar a função, para facilitar
   teste manual — não implementa a lógica pedida no subject. Trate-o como
   material de apoio (pode explicar como usá-lo, o que ele espera de nome de
   função/assinatura) e não como código protegido por `rules/public-repo.md`
   regras 1–2. Esse arquivo é específico do module em que aparece — não presuma
   que todo module vai ter um equivalente nem gere um se não existir.
